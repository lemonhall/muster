- residual_risks:
  1. 同模型自评的橡皮图章风险（与 M0–M6 相同）。缓解：结论一律落成可复现命令或永久门禁。
  2. **没有线上验收**（同 M3–M6）：整套 M7 只在本地 workerd / 本地
     `wrangler dev --local` 上验证。匹配器的闹钟在真实边缘上的最小间隔、
     以及 DO SQLite 的票据量到几千张之后 `processDefault` 的耗时仍未实测。
  3. **匹配器的 bluge 替代品只实现查询子集**（[ECN-0011](../ecn/ECN-0011-match-on-durable-objects.md)
     偏差 4）：客户端用 lucene 语法里没被实现的那几种形状（通配、模糊、字段分组）
     会在 `Add` 时被拒，而不是"当成不匹配"。这是刻意的诚实失败，但确实是行为差异。
  4. **权威对局没有 tick 循环**（ECN-0011 偏差 11）：M7 的权威对局只是一个
     "有成员表与目录记录的对局实例"，没有任何服务端逻辑在跑。真正的 tick、
     `nk.match_create` 与 `tick_rate` / `handler_name` 在 M8。
  5. **运行时的成局回调换成声明式钩子**（ECN-0011 偏差 11）：钩子只认
     `{size, match:{mode,label}}` 这一组条件，比上游的任意 Lua/Go 判定窄得多。
  6. **E2E 的匹配池是跨运行保留的本地 DO 存储**：用例用"带唯一 `run` 属性的查询"
     把这一轮的票圈起来，避免和上一轮的旧票配上（旧票还会在 `max_intervals` 轮之后
     失去发起资格）。这条缓解措施本身是本地存储的产物，不是契约。
  7. **测试收尾噪声**：同时开真 WebSocket 且新建租户的用例文件（
     `tests/integration/match/`、`tests/integration/matchmaker/rounds.test.ts`，
     以及既有的 `tests/integration/channel/`）在 vitest 收尾时会打一条
     `uncaught exception ... EnvironmentTeardownError`。**不影响退出码**（全绿），
     推测是 DO 的完成回调在文件 teardown 时仍在飞行。M7 里只做了"记录在案"，
     没有动它——它不是 M7 引入的，且改它需要动测试池的收尾顺序。
