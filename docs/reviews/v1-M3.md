- residual_risks:
  1. 同模型自评的橡皮图章风险（与 M0/M1/M2 相同）。缓解：结论一律落成可复现命令或永久门禁。
  2. **没有线上验收**。整套 M3 只在本地 workerd 上验证过，没有部署到真实 Cloudflare 账号——这是刻意的预算约束（E2E 不许碰远端资源），但意味着以下三件事在线上仍属未验证：DO 的休眠/唤醒（hibernation）、`state.acceptWebSocket` 在真实边缘的生命周期、以及跨实例投递在真实网络下的时延。
  3. **驱逐恢复在本机测不到**（[ECN-0006](../ecn/ECN-0006-realtime-on-durable-objects.md) §偏差 5）：`evictDurableObject()` 在 `@cloudflare/vitest-pool-workers` 0.22.0 上挂死不返回（含无 socket 的最小探针），`abortAllDurableObjects()` 会把连接一起杀掉。因此"驱逐后靠 socket 元数据重建 presence"这半条设计只测到元数据挂载，平台那一半留给线上验收。
  4. **保活方式与上游不同**（[ECN-0006](../ecn/ECN-0006-realtime-on-durable-objects.md) §偏差 1）：上游是 WS 控制帧 ping（`ping_period_ms=15000` / `pong_wait_ms=25000`），DO 不把控制帧交给应用层，改用"分片 DO 每 20s `/touch` + 注册表 60s 未收到即清并补 leave"。行为等价但**不是字节等价**：安静但健康的连接不会被误杀，而 pong 挂起的检测粒度从 25s 变成 60s。
  5. E2E 门禁本机耗时约 7 分钟，长杆是 10,000 条翻页用例（单跑 278s，预算 900s）；比 M2 记录的 85s 慢，是因为本地 dev proxy 的每请求开销（约 1.4s/请求 × 200 次请求），不是被测代码退化。
  6. `tests/port-guard.ts` 里的动态端口上界（`1024–65535`）是按本机 `netsh` 结果放宽取的；换一台机器时如果动态范围不同，守夜人可能漏占其中几个端口，需要按同样的方式复核（复核命令已写在文件头注释里）。
  7. 守夜人占不到某个端口时**静默跳过**（不报错）。这在"那端口已被真实服务占用"的情况下是安全的——OS 反正不会把它当临时端口分出去；但如果那个服务的绑定只覆盖单个网卡地址（例如只监听 `127.0.0.1`）而 miniflare 走的是另一个地址族，理论上仍可能撞上，属于已知的残余窗口。
