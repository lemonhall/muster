- residual_risks:
  1. 同模型自评的橡皮图章风险（与 M0–M8 相同）。缓解：结论一律落成可复现命令或永久门禁。
  2. **没有线上验收**（同 M3–M8）：整套 M9 只在本地 workerd / 本地 `wrangler dev --local`
     上验证。限流是靠一个**专属本地 dev server**（阈值压到 3）打出真 429 的；
     真实边缘上的 DO 冷启动、DO 被回收时的桶清零时机，以及多租户同时刷屏时
     `idFromName` 的实例分布，都没有实测。
  3. **控制台鉴权与上游不同**（[ECN-0014](../ecn/ECN-0014-console-and-ops.md) 偏差 1）：
     本项目用 tenant server key 取代上游的 console JWT + MFA。现成的上游控制台前端
     不能直接连过来，需要换鉴权方式（或由自家 BFF 代持 server key）。
  4. **控制台只覆盖最小可信内核**（ECN-0014 偏差 6）：用户 + ACL + 钱包账本，
     不是上游 90 多个 console 操作。存储/排行榜/通知/扩展/配置/指标那几组管理端点全部后置。
  5. **内购只有 Apple 是真校验**：Google / Huawei / FacebookInstant 是"已注册但缺凭据"的
     配置守卫；Samsung 与订阅面**不注册**（501，ECN-0014 偏差 7）。要用这几个 provider
     的集成方需要先补校验实现，不只是填凭据。
  6. **限流默认关闭**（ECN-0014 偏差 9）：`RATE_LIMIT_PER_WINDOW` 不配就不过桶。
     也就是说"迁移过来但没配阈值"的部署在上线后**没有**限流保护——这是刻意的
     （上游没有中间件，默认开着是隐性行为变化），但要在部署文档里写清楚。
  7. **限流桶只活在 DO 内存里**（ECN-0014 偏差 4）：DO 实例被回收即清零。
     对"窗口自然滑过"是等价的，但**跨实例的全局配额**做不到——每租户一个 DO 是这套设计的上限。
  8. **`refund_time` 的写入路径还没接**：`migrations/0008_iap.sql` 留了列并保证冲突时不覆盖，
     但退款通知（App Store Server Notifications）面不在 M9 范围内。
  9. **测试收尾噪声**：同时开真 WebSocket、且新建租户的用例文件在 vitest 收尾时会打
     `uncaught exception ... EnvironmentTeardownError`。**不影响退出码**（全绿），
     与 M7 / M8 记录的同一现象同源；M9 只做"记录在案"。
