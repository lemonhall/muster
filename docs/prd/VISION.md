# Muster — 愿景

## 一句话

用 Cloudflare 的边缘原语，重新实现一个**开源游戏后端**的完整功能面：多人对战、排行榜、聊天、好友、群组、匹配、运行时扩展，一套后端在边缘跑起来，开发者不再需要自己运维 Docker、数据库和长连接服务器。

## 最终用户是谁

1. **独立游戏开发者**：有客户端（Godot / Unity / Web），不想为后端付 SaaS 订阅费，也不想维护一台常驻服务器。
2. **柠檬叔自己的游戏项目**：需要一个可自托管、成本可控、能塞进 Cloudflare 免费/低档额度的多人后端。
3. **AI/自动化客户端**：AI agent 也需要账号、房间、排行榜这套原语，且能以 HTTP/WS 直接驱动。

## 核心价值

| 传统做法 | Muster |
|---|---|
| 自己跑 Docker Compose 起后端 + 数据库 | 一个 `wrangler deploy`，或纯本地 workerd 测试环境 |
| 长连接服务器需要机器常驻 | Durable Objects 承载房间/会话，空闲时休眠，零算力计费 |
| 扩容要自己做分片、负载均衡 | 平台自带全球负载均衡与水平扩展 |
| 后端逻辑要单独跑一套服务 | 运行时扩展直接作为独立 Worker 部署与调用 |
| 客户端要重新对接 | 保持线协议兼容，已有客户端 SDK 可直连 |

## 成功长什么样（可验收）

1. **协议兼容**：官方客户端 SDK（JS 为第一验收对象，Godot 为第二）在**不修改 SDK 源码**的前提下，能够完成登录、写入/读取存储、加入频道聊天、提交并读取排行榜、发起匹配并进入对局。
2. **行为对齐**：参考实现（上游，Apache-2.0 授权的开源游戏后端）的公开测试套件所断言的**对外可观测行为**——HTTP 状态码、错误语义、字段名、分页/游标语义、并发顺序保证、时间戳格式——逐项对齐，并有可审计的追溯矩阵，不接受"看起来像就行"。 <!-- doc-hygiene: allow -->
3. **零 Docker 依赖**：全部单元/集成/E2E 测试在本机 workerd 运行时可跑，不需要 Docker、不需要本地数据库进程。
4. **成本可控**：单机可跑通全部 E2E；一个 demo 项目（百级在线、千级账号）落在 Cloudflare 免费或最低档额度内。
5. **可追溯**：每条需求（`REQ-*`）→ 计划（`vN-*`）→ 测试 → 证据，链条完整，无断链。

## 品牌与法务边界（硬约束）

本项目的法律风险点是**产品名与来源混淆**，不是技术借鉴。因此：

1. 项目名、仓库名、包名、Worker 名、数据库名、域名、UI 文案、宣传材料中**不得出现上游产品名或其近似变体**。本项目统称 `muster`。
2. 不复制上游 Go 源码。我们做的是**独立实现**：读它的行为契约、测试场景与公开接口定义，写出自己的实现代码。
3. 线协议兼容所需的上游公开 `.proto` 定义（Apache-2.0）如被引入，必须保留版权头与许可证文本，并在 `NOTICE` 中注明来源与修改情况；仅用于协议编解码，不用于产品命名。
4. 内部文档可以事实性地提及上游项目（技术溯源、致谢、兼容性说明），但不得用于命名、商标、域名、logo 或"某某的替代品"式宣传。
5. 任何对外发布前，必须复核第 1、4 条；这条复核是发布 DoD 的一部分。

## 非目标（v1 阶段）

- 上游的商业云控制台产品（LiveOps / Satori 类）不在复刻范围。
- 上游 Go / Lua 运行时的完整语义（v1 只做 TypeScript 扩展，Python 扩展作为第二批；Lua、Go 明确后置）。
- gRPC（只做 REST + WebSocket 两种客户端面；gRPC-gateway 不做）。
- 多区域强一致数据库语义（上游支持 CockroachDB/Postgres 双后端；本项目用 D1 + Durable Objects 组合替代）。
